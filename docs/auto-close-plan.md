# 열린 탭 보관·supjav 수집 공통 흐름 + 자동 닫기 계획서 (4판, 구현 전)

작성 2026-11-26. 대상: 확장(로컬 탭 보관함) 1.14.0.x. **서버 변경 없음**(0.5.9-test3 그대로).

## 1. 결정된 것

- 탭을 닫는 기준은 **로컬 DB 저장 검증**이다. 서버에 올라갔는지는 닫기 조건이 아니다.
  - 서버에는 평소 동기화로 올라간다. 연결이 끊겨 있으면 대기열에 남았다가, 연결되면 한꺼번에 반영된다.
  - 이 때문에 계획서 3판의 서버 확인 API(`/check`)는 만들지 않는다.
- 수집과 열린 탭 보관은 같은 흐름을 쓴다(2장).
- 수집과 열린 탭 보관은 동시에 돌지 않는다. 먼저 시작한 쪽이 끝날 때까지 다른 쪽은 거절한다.
- 확인창은 로컬 검증이 끝난 뒤, 탭을 닫기 직전에 띄운다.
  - 띄울지 말지는 설정에서 켜고 끈다(기본 켜짐).
  - 설정 스위치는 관리 화면의 열린 탭 보관 탭에 둔다.
- 저장하지 않는 탭:
  - http/https가 아닌 주소(about:, moz-extension:, file:, view-source: 등)
  - supjav 목록 페이지
  - 로딩 중인 탭(빼고 진행한 뒤 몇 개 뺐는지 알림)
- 창의 탭이 전부 닫히게 되면 빈 새 탭 하나를 열어 둔다.
- 관리 화면의 열린 탭 보관도 같은 자동 흐름을 쓴다.
  - 기존 JSON 백업 → 파일 검증 → "닫기 N" 입력 흐름은 없앤다.
  - 백업 탭의 내보내기·가져오기는 그대로 둔다.

## 2. 공통 흐름

| 단계 | supjav 자동 수집 | 열린 탭 보관 |
|---|---|---|
| 0. 잠금 | `busy='collect'` | `busy='capture'` |
| 1. 가져오기 | 목록 탭의 쪽을 넘기며 글 읽기 | 열린 탭 목록 읽기(제외 규칙 적용) |
| 2. 로컬 저장 | 공통 함수 `saveVerified` | 공통 함수 `saveVerified` |
| 3. 로컬 검증 | 공통 함수 `saveVerified` | 공통 함수 `saveVerified` |
| 4. 서버 올리기 | 바로 올리기 시작, 기다리지 않음 | 바로 올리기 시작, 기다리지 않음 |
| 5. 마무리 | 결과 표시 | 확인창 → 검증된 탭만 닫기 → 결과 표시 |
| 6. 잠금 해제 | 함 | 함 |

**`saveVerified(items)`가 2~3단계를 맡는다.**
- 2단계: 같은 주소는 합친다. 수집 글은 화면 순서를 지켜 넣는다(1.13.1.4 방식 그대로).
- 3단계: 저장한 뒤 로컬 DB를 **다시 읽어서**, 이번에 넣은 주소마다 살아 있는 항목이 있는지 하나씩 대조한다. 휴지통에 있는 항목도 "있음"으로 친다.
- 결과로 `{ saved, reused, verifiedUrls, missing }`을 돌려준다.
- 대조에 실패한 주소(`missing`)가 있으면 그 탭은 닫지 않고, 결과에 "검증 실패 n개(열어 둠)"를 알린다.
- DB 쓰기 자체가 실패하면 하나도 닫지 않는다.

**4단계: 서버 올리기**
- `sync.flush()`로 평소처럼 1초를 기다리지 않고 바로 올리기를 시작한다. 끝나기를 기다리지는 않는다.
- 연결이 끊겨 있으면 대기열에 남는다. 머리글의 `서버 연결 안 됨 · n`에 대기열 개수가 보인다.

## 3. 마무리

**supjav 수집**
- 결과 문구에 로컬 검증 결과를 넣는다.
  - 예: "새 게시물 16개 · 보관함 16개 추가(검증 완료)"
- 닫는 탭은 없다. 수집 탭은 그대로 둔다.

**열린 탭 보관**
1. 확인창(설정 켜짐일 때)
   - 예: "12개 저장·검증 완료. 12개 탭을 닫을까요?"
   - 취소하면 저장은 남기고 탭만 닫지 않는다.
2. 검증된 탭만 닫는다.
   - 닫기 직전에 `sameTab`으로 다시 확인하고, 저장 뒤 바뀐 탭은 열어 둔다.
   - 창의 탭이 전부 닫히게 되면 먼저 빈 새 탭을 하나 연다.
   - 닫는 탭은 `suppressedRemovals`에 넣는다. 그래서 작업 시작이 켜져 있어도 완료 처리나 다음 항목 열기가 일어나지 않는다.
3. 결과 토스트
   - 예: "12개 저장·검증 · 11개 닫음 · 바뀐 탭 1개 열어 둠 · 로딩 중 1개 제외"

## 4. 동시 실행 막기

- 백그라운드에 `busy = null | 'collect' | 'capture'`를 둔다.
- 시작할 때 `busy`가 비어 있지 않으면 거절한다.
  - 거절 문구: "supjav 수집 중입니다" / "탭 정리 중입니다"
- 작업이 끝나거나 실패하면 `busy`를 반드시 비운다(`finally`).
- 상태가 바뀌면 화면에 알린다. 하나가 도는 동안 다른 버튼은 비활성으로 두고, 툴팁에 이유를 보여 준다.

## 5. 저장하지 않는 탭 (열린 탭 보관)

- http/https가 아닌 주소 전부
- 비공개 창, 팝업 창, 이 확장 화면(지금처럼)
- supjav 목록 페이지: `supjav.com/ja/category/…`, `/page/N` 포함
- 로딩 중인 탭: 빼고 진행하고, 몇 개 뺐는지 알린다.
- 예전에 저장된 "제한 URL" 항목은 그대로 둔다. 새로 생기지는 않는다.

## 6. 화면

**사이드패널**
- 열린 탭 보관: `[현재 창 | 모든 일반 창] [열린 탭 보관]` 한 줄. 진행 중에는 버튼에 로딩 표시를 한다.
- supjav 칸: 지금 그대로 둔다. 결과 문구에 "검증 완료"를 더한다.
- 빼는 것:
  - `열린 탭 저장 · 백업 · 닫기` 칸
  - `내보내기 · 가져오기 · 설정` 칸
  - 맨 아래 안내 문구

**관리 화면 열린 탭 보관 탭**
- 같은 버튼과 같은 흐름
- "닫기 전 확인창" 스위치(기본 켜짐, PC별 저장)
- 기존 백업·검증·닫기 N 화면은 없앤다.

**관리 화면 백업 탭**
- 그대로 둔다.

## 7. 테스트

- `saveVerified`
  - 정상: 모든 주소 검증됨
  - 일부 대조 실패: 그 주소만 `missing`
  - DB 쓰기 실패: 아무것도 검증되지 않음
  - 이미 있던 주소: 검증됨(휴지통 항목 포함)
- 열린 탭 보관
  - 검증된 탭만 닫힘
  - 확인창: 취소하면 하나도 안 닫힘, 설정이 꺼져 있으면 바로 닫힘
  - 저장 뒤 바뀐 탭은 열어 둠
  - 마지막 탭이면 새 탭이 생기고 창이 유지됨
  - 작업 시작이 켜져 있어도 완료 처리가 일어나지 않음
  - 서버 연결이 끊겨 있어도 닫히고, 대기열에 쌓임
- 제외 규칙: about:, moz-extension:, file:, supjav 목록 페이지, 로딩 중 탭은 저장되지 않음
- 수집: 결과에 검증 수가 들어감
- 동시 실행: 수집 중에는 보관 거절, 보관 중에는 수집 거절, 실패 뒤에는 잠금이 풀림
- 옛 수동 닫기 테스트(백업 검증 전 닫기 막힘, "닫기 N" 입력 등)는 지우고 새 흐름 테스트로 바꾼다.

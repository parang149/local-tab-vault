# 탭 보관함 확장 화면 개편 계획서 (2026-11-25, 초안)

## 목표

- 확장 화면(사이드패널·관리 화면·수집 목록)을 **hitomi-web WEBUI와 같은 모양**으로 다시 만든다.
- 같은 도구(Vue 3 + Nuxt UI 4.12 + Tailwind 4 + lucide 아이콘)와 같은 테마(주 색 emerald, 회색 zinc, 기본 크기 lg, 둥근 카드, 다크 모드)를 쓴다.
- **화면만 바꾼다.** 보관·닫기·백업·동기화·수집 동작과 그 안전 규칙은 그대로 둔다.

## 바꾸지 않는 것

| 파일 | 역할 | 이유 |
|---|---|---|
| `background.js`, `service.js`, `db.js`, `model.js` | 보관함 동작·저장 | 탭 닫기 안전 규칙(백업 확인 후에만 닫기, 입력 확인, 1회용 확인표 등)이 들어 있음 |
| `sync.js`, `collector.js` | 서버 동기화, supjav 수집 | 방금 실제로 검증됨 |
| 화면 ↔ 백그라운드 메시지 형식 | `rpc('list')`, `mutate`, `capture`, `syncInfo` 등 | 새 화면도 같은 메시지를 그대로 보낸다 |

이 부분 테스트(보관함·동기화·수집 52개 중 화면 구조 테스트 제외분)는 그대로 통과해야 한다.

## 구조

```
firefox-extension/
  extension/          ← 실제 확장 폴더(백그라운드 코드 그대로)
    ui/               ← 빌드된 화면이 들어가는 곳(자동 생성, 직접 수정 안 함)
  ui/                 ← 새 화면 소스 (Vite 프로젝트, WEBUI와 같은 버전 고정)
    package.json
    vite.config.ts    ← 화면 3개를 따로 빌드: sidebar / manager / collector
    src/
      sidebar/  manager/  collector/   ← 화면별 시작점
      components/                     ← 공통 카드·목록·대화상자
      rpc.ts                          ← 백그라운드 메시지 호출 모음
      theme.ts                        ← WEBUI와 같은 색·크기 설정
```

- `npm run build` 한 번으로 화면 빌드 → `extension/ui/`에 복사 → `dist/local-tab-vault-<버전>` 생성까지 한다.
- `manifest.json`의 사이드패널·관리 화면 경로만 새 화면으로 바꾼다.
- **WEBUI 코드와 직접 연결하지 않는다.** frontend 폴더를 불러오면 한쪽을 고칠 때 다른 쪽이 깨질 수 있다. 같은 테마 설정과 필요한 작은 컴포넌트(균등 탭, 선택 상자 등)는 복사해서 맞춘다.
- 아이콘은 빌드에 넣는다. 외부 아이콘 서버나 글꼴 서버에는 접속하지 않는다(WEBUI와 동일).

## 보안 정책(CSP) 확인 사항

- Vue 화면은 미리 컴파일되므로 `script-src 'self'`로 동작한다.
- Nuxt UI는 실행 중에 색 변수용 `<style>`을 넣거나 팝업 위치를 style 속성으로 정하는 경우가 있다. 지금 확장 CSP(`style-src 'self'`)에서 막힐 수 있다.
- 1단계에서 먼저 시험한다. 막히면 빌드 때 CSS로 미리 만드는 방법을 우선 시도하고, 그래도 안 되면 `style-src`에 `'unsafe-inline'`을 추가한다. 스크립트 정책은 그대로 둔다.

## 화면 설계

### 사이드패널 (폭 약 300~400px, WEBUI 휴대폰 화면과 같은 느낌)

위에서부터 다음 순서로 둔다.

1. **머리줄**: "탭 보관함", 미완료 개수, 전체 화면 열기(테마 버튼은 밝은 테마를 추가할 때 다시 넣음)
2. **작업 시작 스위치**(USwitch): 켜면 탭을 닫을 때마다 다음 항목을 연다. 상태 문구는 작게 표시한다.
3. **연동 상태 칩**: 연결됨(초록) / 다시 연결 중(노랑) / 꺼짐(회색), 서버 미반영 N개
4. **supjav 수집 카드**: 범위(새 글만 최대 N쪽 / 날짜까지), 수집·중지 버튼, 진행 막대와 문구
5. **열린 탭 보관**: 범위 선택과 보관 버튼
6. **목록**
   - 상태 균등 탭: 미완료 / 완료 / 휴지통
   - 정렬(최신순 기본), 검색
   - 항목 카드: 제목 두 줄, 사이트 주소, 상태 배지, 태그(썸네일 없음)
   - 항목 오른쪽 `…` 메뉴: 확인 중 / 완료 / 메모·태그 / 휴지통
   - 선택 모드에서 한꺼번에 처리
   - 아래에 쪽 이동(UPagination)

### 관리 화면 (새 탭 전체 화면)

- 위쪽 균등 탭으로 영역을 나눈다: **보관함 · 열린 탭 보관 · supjav · 백업 · 연동**. 지금처럼 긴 한 페이지(01~04)를 스크롤하지 않는다.
- **보관함**: 사이드패널과 같은 목록을 넓게 보여 준다. PC 폭에서는 2열 카드나 표 형태로 바꿀 수 있게 한다(WEBUI의 그리드/목록 전환과 같음).
- **열린 탭 보관**: 지금의 단계형 흐름(①백업 → ②확인 → ③기존 탭 닫기)을 단계 표시(UStepper 또는 번호 카드)로 바꾼다. 확인 입력 규칙은 그대로 둔다.
- **supjav**: 별도 수집 목록 화면으로 가는 입구와 수집 설정만 둔다. 수집 목록은 합치지 않는다.
- **백업**: JSON / TXT / HTML 내보내기, 가져오기, 컨테이너 권한
- **연동**: 서버 주소, PC 이름, 상태, 다시 받기, 끄기

### 공통

- 브라우저 기본 `confirm()` 창을 모두 UModal 확인창으로 바꾼다. 영구 삭제처럼 되돌릴 수 없는 작업은 빨간 버튼으로 표시하고 개수를 보여 준다.
- 완료 알림은 화면 아래 토스트(UToast)로 띄운다. 지금은 아래 고정 문구로 보여 준다.
- 버튼과 입력칸 크기, 글자, 간격은 WEBUI의 기본 크기(lg)에 맞춘다.

## 테스트

- 동작 테스트(보관함·닫기 안전·동기화·수집)는 그대로 유지하고 계속 통과해야 한다.
- 지금 HTML 구조를 직접 확인하는 화면 테스트(관리/사이드패널 컨트롤, 범위 칸 위치)는 새 Vue 컴포넌트 테스트로 바꾼다.
  - 버튼이 맞는 메시지를 보내는지
  - 확인창 없이 영구 삭제가 되지 않는지
  - 숨겨진 패널 안에 설정이 들어가지 않는지
- 빌드 결과물에 외부 주소(아이콘·글꼴 서버) 요청이 없는지 검사한다.
- 실제 확인은 리브레울프 사이드패널(좁은 폭)과 관리 화면(PC 폭)에서 한다. 밝은 테마와 어두운 테마 모두 본다.

## 정해야 할 것

1. **관리 화면 배치**: 결정됨. 탭 5개로 나눈다.
2. **수집 목록 화면**: 결정됨. 합치지 않고 **별도 화면으로 유지하며 가장 중요한 화면**으로 다룬다(사용자). 단계 1 직후 가장 먼저 개편한다. 표시 데이터는 **서버 보관함 기준**이다(결정됨).
   - 보관함(서버와 동기화된 캐시)의 supjav 항목을 보여 준다. 다른 PC에서 수집한 글도 함께 보인다.
   - 완료·휴지통 상태를 표시하고 바꿀 수 있으며, hitomi-web supjav 탭과 실시간으로 맞는다.
   - 이 PC의 별도 수집 기록 DB는 화면에 쓰지 않는다. 수집할 때 마지막 실행 결과를 보여 주는 용도로만 남긴다.
3. **사이드패널 썸네일**: 결정됨. 표시하지 않는다.
4. **기본 테마**: 결정됨. 일단 항상 어둡게 한다.
   - 나중에 밝은 테마를 추가할 수 있게 색은 Nuxt UI 테마 변수로만 지정하고, 화면 코드에 색을 직접 쓰지 않는다.
   - 지금의 테마 전환 버튼은 숨기되, 저장된 테마 설정은 남겨 둔다.
